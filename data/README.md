# data

Computed results in plain formats (JSON, JSON lines, text). Every file, or directory of files, has a sidecar
`<name>.meta.json` (or a `README.meta.json` / `*.meta.json` covering a group of files) with: what the file contains
(`description`), when and with what code it was computed (`date`, `code`, `commit` of the collaboration's working
repository, `command`), how it was checked (`checked`) and its limits (`caveat`). Labels R-0xx / T-0xx refer to the
results and computations of `summary/fortuity-summary.pdf`, whose appendix A lists, for each, the code that produced
these files.

## Formats

- **Highest-weight scans** (`*_hw_cohomology_*.jsonl`, and the `*_records/` directories): one JSON line per sector
  `(N, lam = (q1, q2, q3), n = 2J)`, as written by `fortuity.hwcoh.run_sectors`: `m` (exact multiplicity of
  highest-weight vectors, `m_d` per fermion degree), `r_up` (rank of Q from the sector at 2J + 1 into this one, i.e.
  the dimension of the exact subspace; Q lowers 2J by one), `grav` (multi-graviton classes modulo exact), `check`
  (exact-dimension self-check), plus run information. The multiplicity of the irrep in cohomology is
  `h(n) = m(n) - r_up(n-1) - r_up(n)`, and `h - grav` counts non-graviton classes.
- **Assembled columns** (`bmn_hw_cohomology_*.json`): per column `j, lam, rep, euler, index, all_checks` and per
  sector `twoJ, E, m, h, grav, BH = h - grav, check` (`python -m fortuity.hwcoh.to_json`).
- **Indices**: series coefficients per level `j` and SU(3)_R content, from exact Haar integrals.
- **Operators** (`*_rep_*.json`, `cckll_*`, `dmk_o330_hw.json`, `graviton_class_vanishing_on_diagonal_j24.json`):
  multi-trace terms with exact integer or rational coefficients, in the word encoding of `fortuity.bmn.words`.

| `so_sp/` | SO(2N+1) vs USp(2N) indices (N = 3..6); direct cohomology at the first differences; complete scans below them (SO(7) j <= 18, SO(9) j <= 22, SO(11) j <= 24) and at j = 26; non-graviton representatives; block restrictions | R-004, R-005, R-006, R-011, R-016, R-018, R-021 |

| `fullso/` | SO(7) and USp(6) with all letters at levels 18, 20, 22: scans, census, graviton classification | R-025 |

Each file is a single copy: drivers and checks in `scripts/` read these files instead of keeping their own copies.
Files of a few MB at most; large intermediate objects (evaluation matrices, caches, representatives with ~10^5-10^6
terms) are not stored and are regenerated by the scripts.

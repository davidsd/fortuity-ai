# Fortuity: fortuitous BPS states of N=4 SYM at weak coupling

Results, code and data on the 1/16-BPS cohomology of N=4 super Yang-Mills theory at
finite rank: which classical Q-cohomology classes are multi-gravitons and which are fortuitous (black-hole
candidates), for the gauge groups SU(2), SU(3), SU(4), SU(5), SO(5), SO(7), SO(9), SO(11), SO(13), USp(6), USp(8),
USp(10), USp(12) and G2, and what happens to the lowest classes at one and two loops.

**Start with [`summary/fortuity-summary.pdf`](summary/fortuity-summary.pdf).** It states every result with its
checks, compares it with the published literature equation by equation, lists what is open, and in its appendix A
maps every result to the code and data in this repository.

The computations, the code and the summary were produced by Claude (Anthropic's AI model) working as AI agents for
the members of the collaboration, who set the questions and checked and reviewed the results.

The collaboration's [statement](https://docs.google.com/document/d/1BhHApchsxugrAp8K98tPHiEgZ357fRR-Z5ZAi4pEsrg/edit?tab=t.0)
explains how the project was run and why the results are released here rather than as a paper on the arXiv.

## Layout

| path | contents |
|---|---|
| `summary/` | the summary (`fortuity-summary.tex`, compiled `fortuity-summary.pdf`) |
| `code/` | the Python library `fortuity` and its tests ([`code/README.md`](code/README.md)) |
| `data/` | computed results in plain formats, each with a `.meta.json` provenance record ([`data/README.md`](data/README.md)) |
| `scripts/` | drivers, cluster job files and run outputs behind each result, by area ([`scripts/README.md`](scripts/README.md)) |

## Quick start

```
python3 -m pip install -e 'code[dev]'     # numpy, sympy, pytest; or: export PYTHONPATH=$PWD/code
cd code && python3 -m pytest -q           # library tests (a few minutes); FORTUITY_SLOW=1 adds the slow ones
python3 -m fortuity.bmn.r002_check        # the SU(3) graviton class that vanishes on diagonal matrices
python3 -m fortuity.full.lifting so7      # one-loop lifting of the SO(7) fortuitous class
```

Some scripts also use scipy, mpmath and matplotlib, and the GPU rank code uses CuPy. Scripts that are not library
modules expect `PYTHONPATH` to contain `code/` (and some read the repository root from `REPO`). Appendix B of the
summary lists further one-line checks with their run times.

## Main results

| | result | where |
|---|---|---|
| SU(2) | complete scan to level j = 44: 186 classes, 20 non-graviton; 5 lift at one loop; the threshold class has no lifting partner at any order (given a superconformal selection rule) and is protected by the index | summary sec. 3 |
| SU(3) | the threshold operator of arXiv:2312.16443 is Q-exact; the first black hole is at j = 30, brane-fused, C-odd, unlifted at one loop; all black holes below j = 34 are fused by scalar branes; the first class outside that family is at j = 34 | summary sec. 4 |
| SU(4) | no non-graviton class for j <= 30 | summary sec. 5 |
| SO / USp / G2 | first SO(2N+1)-USp(2N) difference at j = 4N+6 in Sym^(N-3)[2,0]; the SO(7), SO(9), SO(11) classes are the lowest, fused on the SO(7) core, lifted at one loop; no class in G2 for j <= 28 | summary sec. 6 |
| structure | charge-conjugation parity of gravitons, twisted and kernel-parity indices, non-Coulomb gravitons, brane fusion, selection rules, a two-loop supercharge on derivative-free words | summary sec. 7 |

## Conventions in one paragraph

BMN-sector sectors are labelled (2J; q1, q2, q3) with q_I = R_I + J; the level j = 2(q1 + q2 + q3) is the power of t
in the BMN index, the energy is E = j/2 - J and the number of letters is q1 + q2 + q3 - 2J. An SU(3)_R highest weight
(q1 >= q2 >= q3) is a "column", the irrep [q1 - q2, q2 - q3]. Ranks are computed by random evaluation over F_p,
p = 2^26 - 5, certified sector by sector against exact dimensions (summary sec. 2.4).

## What is and is not here

The files are the ones that produced the results, copied from the collaboration's working repository on
2026-10-14 with imports updated to the library layout and machine-specific paths and accounts in cluster job files
replaced by placeholders (`${REPO}`, `${SCRATCH}`, `${ACCOUNT}`, ...). Working notes, logs and planning files of the
collaboration are not included; their content relevant to the results is in the summary. Large intermediate files
(evaluation matrices, caches, explicit representatives above ~10 MB) were never stored and are regenerated by the
scripts.
